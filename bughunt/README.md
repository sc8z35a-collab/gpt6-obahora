# 共同バグ調査 共有ボード（リーダー: A）

**全エージェントはまずこのファイルを読むこと。** 連絡はすべてリモートの `genspark_ai_developer` ブランチ上の `bughunt/` ディレクトリで行う。

## 権限（開発者から明示的に許可済み）
- 開発者（リポジトリ所有者）から **「デバッグのためなら自由に何をしてもいい」** と明示的に許可されている。
- 現状使える全ツール・ハーネス・その他便利機能（Bash、ブラウザ/Playwright、ヘッドレスChromium、スクリーンショット、画像解析、Web検索、npm/pip導入、GetServiceUrl など）を共有し、バグ探索のためにありとあらゆる手段を自由に行使してよい。
- ただし **明らかなコード破損を意図的に起こさないこと**。本体コード（js/css/html）は原則変更しない。調査用スクリプトは `bughunt/tools/` に置く。
- 環境: メモリ約1GB・2CPU。ブラウザは同時に1つまで・使い終わったら必ず閉じる。重いプロセスを放置しない。

## 目標
- 合計60件以上（コード・見た目・システム面）。**重大なバグを優先**。
- 作業は頻繁にコミット＆プッシュ（環境が消える恐れあり）。目安: バグ3件ごと or 15分ごと。

範囲外のバグを見つけても記録してよい（重複は `DUP?` と書く）。書く前に他人のファイルを `git pull` で確認し重複を避ける。

## バグ記述フォーマット（1件ずつ）
```
### X-001 [重大度: Critical/High/Medium/Low] [種別: code/visual/system] タイトル
- 場所: ファイル:行
- 内容: 何が起きるか
- 根拠/再現: コード抜粋 or 手順 or 検証結果
- 修正案: （任意）
```

## 開発環境トラブル
各自 `env_X.md` に「発生したエラー（原文）／原因／解決法」を書く。**環境そのもののエラー**（ツール、ブラウザ起動、メモリ、git、ネット等）が対象。困ったら他人の env ファイルを先に読むこと。

## git 運用（衝突回避）
- 自分のファイルだけ編集する（README.md はリーダーのみ）。
- `git pull --rebase origin genspark_ai_developer` → 編集 → `git add bughunt/ && git commit -m "bughunt(X): ..." && git push origin HEAD:genspark_ai_developer`。push拒否時は pull --rebase してやり直す。
- 強制push禁止。
